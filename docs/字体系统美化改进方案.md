# 矢量字体美化改进方案

## 结论

当前矢量字“不美观、不精致”，主要不是 FreeType 不能用，而是字体选择、字形覆盖率处理、描边方式、字面度量和对话框布局被混在了一起。现在的实现已经能正确显示中文字，但更接近“把字画出来”，还没有恢复原版界面的字重、边缘、间距和垂直节奏。

当前最值得优先修正的地方有四个：

1. 默认直接打开 `.ttc` 的 face 0，中文很可能使用了日文字形；
2. `Medium + gain 130% + 黑色膨胀描边` 组合容易让字发粗、发脏、像贴纸；
3. `dilate` 最大值膨胀会把抗锯齿边缘变成硬轮廓，细节和转角不够平滑；
4. 对话框基线只用 `ascent` 推算，字体换了以后字面在框内的上下位置、行距和左右节奏不一定合适。

## 一、首先确认中文字体 face 是否正确

`NotoSansCJK-Medium.ttc` 是字体集合，不是只有一个字体。当前 `src/ft2.rs` 调用 `FT_New_Face` 时固定传入 face index `0`。在常见的 Noto CJK 文件中，face 0 通常是 JP，后面才是 KR、SC、TC、HK。也就是说，即使文件名叫 `NotoSansCJK-Medium.ttc`，当前引擎也可能用日文字形绘制中文。

这会直接影响以下字形的视觉风格：

- `骨、直、着、裏、国、门、广、发` 等中日韩字形差异；
- 部件比例和重心；
- 部分偏旁的收笔和转角；
- 中文补丁文字与 UI 标签之间的一致性。

建议修改 FreeType FFI：

```text
FT_New_Face(library, path, face_index, &face)
```

并增加一个可配置的 `face_index`：

```text
WA2_FONT_FACE=2        # 中文简体通常选择 SC face
WA2_FONT_FACE=0        # 日文模式可选择 JP face
```

更稳妥的方案是让 `WA2_FONT` 支持 `路径#索引`，例如：

```text
WA2_FONT=/usr/share/fonts/opentype/noto/NotoSansCJK-Medium.ttc#2
```

程序启动时打印实际打开的字体族名和 face index，避免只看到文件路径却不知道使用了哪一个 face。也可以通过 `fc-scan` 或 `fc-match` 对照验证。

这是当前最可能造成“字形不精致”的基础问题，应在调整字重和描边之前先解决。

## 二、把字形外观拆成四个独立参数

现在的 `VectorFont` 同时使用：

- 字体文件本身的字重；
- `WA2_FONT_BOLD` 的形态膨胀；
- `WA2_FONT_GAIN` 的覆盖率放大；
- `outline_for(size)` 生成的黑色描边。

这四者叠加后很容易过重。建议把参数分为四类，并分别调试：

```text
font face       决定字形结构和基本字重
font weight     决定笔画粗细
ink gamma       决定抗锯齿边缘的明暗
shadow/outline  决定文字与背景的分离方式
```

建议先用下面的基线配置观察实际效果：

```text
中文正文：Noto Sans CJK SC Medium 或 Regular
WA2_FONT_BOLD=0
WA2_FONT_GAIN=105~115
正文描边半径：0~1 像素
阴影：偏移 1 像素，透明度 70~130，而不是全黑硬轮廓
```

如果使用 Regular 字体后笔画太细，应优先尝试真正的 Semibold/Medium face，再考虑 `BOLD=1`。不要同时提高 gain、增加 bold、扩大 outline；否则笔画内部会糊成一块，字间空隙也会缩小。

## 三、改掉线性的覆盖率增益

当前逻辑大致是：

```text
new_alpha = min(old_alpha * gain / 100, 255)
```

这种线性放大在 130% 左右会迅速把半透明边缘推到 255，导致：

- 细笔画突然变粗；
- 转角出现锯齿；
- 字内反白空间缩小；
- 不同字号的视觉重量不一致。

建议改成可调的覆盖率曲线，保留高覆盖率区域，同时让边缘渐变自然：

```text
a = old_alpha / 255
new_alpha = 255 * pow(a, gamma)
```

其中 `gamma` 可以从 `0.90~1.00` 试起。`gamma=1.0` 等于不改变覆盖率；小于 1 会适度提亮边缘，但不会像 130% 线性乘法那样突然饱和。设置项可以改名为 `WA2_FONT_GAMMA`，旧的 `WA2_FONT_GAIN` 保留兼容，但不要再把两种算法混用。

验收时应分别统计：完全不透明像素、半透明边缘像素和空白像素。漂亮的正文不应追求“所有字都是 255”，而应保持清晰的实心笔画和连续的抗锯齿边缘。

## 四、不要用最大值膨胀直接做黑色描边

当前 `dilate` 使用圆形邻域最大覆盖率，然后把外圈填成黑色。这个方法实现简单，但会产生硬边：

- 黑色描边在每个方向都同样厚，显得卡通；
- 小字号下一个像素就可能占很大比例；
- 复杂汉字的内孔会被描边挤窄；
- 抗锯齿边缘被再次扩张，出现脏边。

建议按以下顺序改进：

### 方案 A：优先采用软阴影

对白正文使用白色字形，加一个轻微的黑色偏移阴影：

```text
先画黑色 coverage，位置 (x+1, y+1)，alpha 70~130
再画白色 coverage，位置 (x, y)，使用原始 alpha
```

这通常比整圈黑边更接近视觉小说的正文效果，也更不容易破坏汉字内部空间。

### 方案 B：保留细描边但降低透明度

如果复杂背景确实需要轮廓，描边半径保持 1 像素，描边 alpha 控制在 90~170，不要直接使用 255 黑色。描边应该帮助分离背景，而不是成为字形的一部分。

### 方案 C：使用距离场或 FreeType Stroker

如果后续需要任意半径的稳定描边，可以通过手写 FFI 调用 `FT_Stroker`，或在位图 coverage 上建立小型距离场。不要继续扩大 `dilate` 半径来模拟粗体和描边，因为粗体与描边的形态目标不同。

## 五、修正 FreeType 栅格化模式

当前 `FT_Load_Glyph` 使用 `FT_LOAD_RENDER`，属于可用的基础路径，但没有明确指定提示模式。26px 左右的 CJK 正文对提示方式很敏感。

建议在 FFI 中支持可选 load flags，并至少比较以下组合的截图：

```text
FT_LOAD_RENDER | FT_LOAD_TARGET_LIGHT
FT_LOAD_RENDER | FT_LOAD_FORCE_AUTOHINT | FT_LOAD_TARGET_LIGHT
FT_LOAD_RENDER                         # 当前基线
```

推荐先以 `TARGET_LIGHT` 作为正文候选。它通常能减少小字号笔画忽粗忽细的问题。不要一开始使用 MONO，也不要直接使用 LCD 子像素渲染，因为最终画面是 RGBA 纹理，子像素颜色会在缩放和合成后留下彩边。

同时检查以下事项：

- FreeType 的 bitmap pitch 负数处理已经存在，应保留；
- `FT_Select_Charmap(UNICODE)` 应继续保留；
- `FT_Get_Char_Index` 返回 0 时应使用明确的缺字回退，不要默默留下不规则空洞；
- `.ttc` 的 face index 必须和语言模式一致。

## 六、用字体度量做布局，不要只用 ascent

当前正文基线近似为：

```text
baseline = DIALOG_TEXT_Y + ascent
```

这隐含假设 `DIALOG_TEXT_Y` 是字面顶端，而且字体的 ascender 正好等于视觉顶部。不同 face、字号和数字/拉丁字符会破坏这个假设，结果就是文字看起来偏上、偏下，或者三行间距不稳。

建议从 FreeType 读取并缓存：

```text
ascender
descender
line_gap
cap_height（如果字体提供）
```

然后以“行框”定位：

```text
line_box_top = DIALOG_TEXT_Y
line_box_height = DIALOG_LINE
baseline = line_box_top + (line_box_height - ascender - descender) / 2 + ascender
```

姓名和正文应使用不同的基线参数。姓名位于框边缘，正文位于椭圆窗口内部，不能共享同一个简单的 `ascent` 偏移。

同时把布局坐标改为定点数或 26.6 格式，最后一步才四舍五入到像素。当前 `v * wh / 720` 使用整数截断，在 1080p、1440p 和窗口缩放时会造成一像素级的跳动，尤其会影响基线和行距。

## 七、修正字距、宽度和换行

当前正文使用每个 glyph 的 `advance` 逐字推进，CJK 基本可用，但还缺少更精细的排版处理：

- 拉丁字母、数字和标点没有 kerning；
- 中英文混排时没有按脚本调整字宽；
- 只检查 advance，未检查实际 glyph ink 是否越过边界；
- `dialog_lines` 去掉 ruby 读音后，没有保留原版的阅读节奏；
- 全角标点、半角标点和英文空格的间距可能不统一。

建议增加：

1. `FT_Get_Kerning` 的可选 FFI，至少用于拉丁字母和数字；
2. CJK 使用全宽 advance，ASCII 使用实际 advance；
3. 对最后一个字符按实际 ink bounding box 做裁剪判断；
4. 统一处理全角空格、半角空格、引号和省略号；
5. ruby 先解析成结构化 token，正文和注音分别排版，而不是简单删除标签。

对白原文已经预分行时，不要重新随意换行；但是仍应在渲染前验证该行的实际宽度，必要时使用与原版一致的压缩字距或换行规则。

## 八、按用途区分正文、姓名和 UI 标签

不应让所有文字都使用同一套白字黑边参数。建议建立三种文字样式：

| 样式 | 字体建议 | 颜色 | 阴影/描边 | 主要用途 |
| --- | --- | --- | --- | --- |
| 正文 | SC Medium/Regular | 暖白或纯白 | 轻微偏移阴影 | 对话正文 |
| 姓名 | Medium 或 Semibold | 金色/白色 | 更窄的阴影 | 角色名 |
| UI 标签 | Regular/Medium | 素材指定颜色 | 通常不描边 | 设置、存档、时间线 |

设置、存档和时间线标签位于不透明底板上，应该使用 `draw_flat` 或低透明度阴影，不能沿用对白的黑色轮廓。正文位于复杂 CG 上时才需要更明显的分离效果。

## 九、建议的实现顺序

1. **修正 TTC face index**：支持 `WA2_FONT_FACE` 或 `路径#索引`，启动时打印族名和索引。
2. **建立字体样式表**：正文、姓名、UI 分开保存字号、颜色、gamma、阴影和描边参数。
3. **把默认 gain 降到中性范围**：先测试 `105~115`，关闭 `BOLD`，描边改成轻微阴影。
4. **加入 load target 对比**：在 720p、1080p、4K 各截同一段中英文混排文字。
5. **修正基线和行框**：使用 ascender、descender、line gap 计算，不再只加 ascent。
6. **增加 kerning 和混排宽度处理**：先处理英文、数字和标点，再处理 ruby。
7. **最后再调字形粗细**：只有 face、栅格化、alpha 和布局都稳定后，才调整 bold。

## 十、验收方式

不要只凭单个字判断。应制作固定字体样张，包含：

```text
中文正文：春希、雪菜、冬马和纱、已经落尽
复杂字：鬱、邊、體、樂、觀、發、臺、裏
标点：，。！？「」『』……
混排：WHITE ALBUM 2 100% 2026
三行对白和一行姓名
```

每种字体配置在 1280×720、1920×1080、2560×1440 下导出 TGA，对比：

- 字形是否为正确的 SC/JP face；
- 细笔画是否连续；
- 黑边是否压缩内孔；
- 三行基线是否等距；
- 中英文混排是否跳动；
- 文字缩放后是否有彩边、灰边或锯齿；
- 姓名与正文是否具有层次，而不是一套样式复制到底。

当前已有字体相关单元测试，能够验证字形存在、覆盖率和窗口缩放，但这些测试不能判断“像不像原版”。应补充固定样张的像素截图或人工视觉检查。测试仍应保持：

```bash
cargo build --release
cargo test
```

在没有完成 face index、alpha 曲线、基线和描边调整前，不建议继续提高 `WA2_FONT_GAIN` 或 `WA2_FONT_BOLD`；那只会把现有问题放大。

## 落实情况（2026-10-18）

### 已落地

| 方案条目 | 落实 |
| --- | --- |
| 一、TTC face index | `Ft::open` 接受 face index；`WA2_FONT` 支持 `路径#索引`，另有 `WA2_FONT_FACE`；默认 `NotoSansCJK-Medium.ttc` face 2（SC，`fc-scan` 确认顺序为 JP/KR/SC/TC/HK）。启动日志打印族名、样式、face 序号与全部旋钮：`font: Noto Sans CJK SC Medium (face 2 of 5) 26px gamma=0.90 bold=0 edge=1px@160 hint=light` |
| 二、四参数分离 | 字重（face/`WA2_FONT_BOLD`）、覆盖率曲线（gamma）、描边半径/透明度（`WA2_FONT_EDGE`/`WA2_FONT_EDGE_ALPHA`）、软阴影（`TextStyle::shadow`）互相独立，默认 `BOLD=0`、`gamma=0.90`、`edge=1px@160`、阴影偏移 (1,1)@110 |
| 三、gamma 曲线 | 覆盖率改为 `255*a^gamma`（`WA2_FONT_GAMMA`，千分比，默认 900）；`WA2_FONT_GAIN` 仅在该变量被显式设置时回到旧的线性放大，两条曲线不混用。26px 实心率从旧线性 130% 的 ~0.79 降到 ~0.66（按 glyph coverage mask 统计；合成后的样张 A/B 测得 0.673→0.519，方向与降幅一致，绝对值因口径不同不可直接对比），保留连续抗锯齿带 |
| 四、描边改软 | 描边透明度可调（默认 160 而非 255）；正文增加偏移软阴影；`stamp_styled` 单遍完成 ink>edge>shadow 三层优先级，阴影只取字形自身 coverage 平移 |
| 五、栅格化 | `FT_LOAD_RENDER | FT_LOAD_TARGET_LIGHT` 为默认，`WA2_FONT_HINT=light/normal/auto/none` 可切；pitch 负数、UNICODE charmap 保留。缺字回退：`FT_Get_Char_Index` 返回 0 时 `Ft::glyph` 直接返回 None（此前会加载 glyph 0 画成 .notdef 豆腐块），由 `missing_tile` 留一个等宽空档并**按字符只警告一次**（`font: <族名> has no glyph for U+1F600 - leaving a gap`） |
| 六、度量布局 | 从 `size->metrics` 读 ascender/descender/height（26.6 已缩放）；正文与姓名各自行框，`baseline = top + (box_h-asc-desc)/2 + asc`；**排版笔尖全程用 26.6 定点**（`advance_266`/`kerning_266`，落墨时才取整），`sx/sy/layout_px` 四舍五入 |
| 七、字距混排 | 新增 `FT_Get_Kerning`（26.6 原始值），仅对相邻 ASCII 生效；CJK 保持全宽 advance；换行判断按字形 ink 右缘；`measure` 计入 kerning；**宽度策略**：`full_width_punct()` 把原版 28px 等距 cell 里的 CJK 标点（、。「」『』""''…――※ 等）与**全角形式区 U+FF01–FF60、U+FFE0–FFE6**（，？！～（）：等）统一按全宽推进，不受字体文件影响——Noto 本身已给全宽，唯一例外是 U+2014（23px）会被拉回 26px；拉丁与半角空格仍按字体比例（`±×÷°§¶‰` 等拉丁符号不进全宽集，"10±5" 不会被撑开）；**半角形式区 U+FF61–FF9F 故意不收**（它们本来就是窄的），测试里有反向断言防止范围写宽 |
| 八、三种样式 | `TextRole::{Body,Name,Ui}` + `TextStyle`：正文（纯白+细边 160+软阴影）、姓名（暖白 255,246,226 + 更硬边 170、无阴影，与正文拉开层级）、UI 标签（`labels_rgba`/`line_rgba`/`block_rgba` 走 `TextRole::Ui`，无描边无阴影，可带自身颜色） |
| 十、验收 | 新增 `wa2-native font-sample <out.tga> [w] [h]` 固定样张（正文/复杂字/标点/中英混排 + 真实对话框路径的姓名与三行对白），720p/1080p/1440p 均已导出核对 |

### 顺带修复

`Surface::save_tga` 原先每像素一次 `write_all`（1280x720 一帧 92 万次系统调用，`WA2_FRAME_DUMP` 抓一帧要一分钟）。改为按行缓冲一次写入，截图验收恢复可用。
