# 设置界面视觉改进方案

## 截图诊断

从 `截图 2026-10-18 17-49-21.png` 看，当前设置界面已经能显示中文和控件状态，但整体观感确实偏脏。主要问题不是颜色太亮，而是“旧文字残留、覆盖修补痕迹、新文字字距和控件布局”同时存在。

截图中可以看到几类明显现象：

- 左侧中文标签周围有黑青色碎点和残留笔画；
- 按钮内部有旧英文/旧中文的暗色影子，部分控件像被擦过后重新贴字；
- 新中文使用了较大的字面和较宽的字距，和原素材的细线框、雪花装饰不在同一套视觉比例里；
- 滑块的 `0%`、`100%`、`FAST`、`SLOW` 与轨道和按钮距离不一致，底部文字有压线现象；
- 选中态和悬停态都偏亮，青色填充与白字叠加后局部发白；
- 底部导航和页签使用了另一套字面、字号和间距，看起来像不同界面拼接在一起；
- 左侧大面积纯黑区域和被擦除后的不均匀纹理形成对比，放大了脏点的可见度。

最主要的根因是：当前流程先把带有原版文字的页面素材铺上去，再通过 `wipe_baked_captions`、`nearby_fill` 和 `wipe_chrome_captions` 猜测哪些像素属于文字并进行修补，最后再叠加矢量字。这种方法适合快速验证位置，不适合作为最终视觉方案。像素分类一旦把抗锯齿边缘、雪花、细框或暗色英文误判，修补后就会留下碎边和色块。

## 一、先改变合成策略：清洁底图优先

最终界面不应依赖每帧的“擦字”。建议把设置界面拆成三层：

```text
clean_base       页面背景、分隔线、雪花、边框、滑块底轨
state_layer      选中、悬停、滑块填充、按钮状态
text_layer       中文标签、按钮文字、页签和底部导航
```

`clean_base` 应该在资源构建阶段生成一次，运行时只读取。运行时不再对已经合成好的页面做大面积像素猜测。

推荐生成以下派生资源：

```text
data/cache/ui/menu/page1_clean.tga
data/cache/ui/menu/page2_clean.tga
data/cache/ui/menu/page3_clean.tga
data/cache/ui/menu/page1_mask.tga
data/cache/ui/menu/page2_mask.tga
data/cache/ui/menu/page3_mask.tga
```

其中 `clean` 只去除原版文字，保留边框、规则线、雪花和滑块结构；`mask` 记录文字区域和控件区域，运行时用于保护边框和装饰。缓存由 `tools/build_ui_cache.py` 生成，素材变更后重新运行，不要在 `menu.rs` 的绘制循环里重复修补。

如果没有干净的原始页面素材，清理也应使用固定的矩形和颜色模型，而不是逐像素寻找最近邻：

- 左侧黑色标签区用纯黑或稳定的黑色渐变重建；
- 按钮内部按纵向渐变重建，保留左右雪花区域；
- 页签内部从同一状态的无字区域采样整列渐变；
- 细框、规则线、雪花区域列入保护掩码，绝不参与填充。

这样可以消除截图中最明显的碎点和旧字影子。

## 二、删除或降级运行时擦字算法

当前 `wipe_baked_captions` 的问题不是阈值还不够多，而是它无法可靠区分：

- 原版文字的抗锯齿边缘；
- 青色规则线；
- 雪花装饰；
- 按钮边缘高光；
- 选中态的青色填充；
- 英文副标题的暗色笔画。

建议保留这些函数仅作为旧资源的兼容后备，并在正常中文设置界面中改为：

1. 读取预生成的 clean 页面；
2. 按状态叠加 gold/cyan 的局部控件图层；
3. 最后绘制中文文字。

不要再对完整合成帧执行 `nearby_fill`。如果必须保留旧路径，应将清理范围限制为预先标注的文字矩形，并使用每个矩形自己的背景模型，而不是全页亮度阈值。

## 三、设置界面要使用独立的字体样式

设置界面不应直接继承对白字体的视觉参数。对白需要在 CG 上保持可读性，设置页面文字位于规则、按钮和深色底板上，应该更轻、更平、更干净。

建议建立独立样式：

| 元素 | 建议字体 | 逻辑字号 | 颜色 | 描边/阴影 |
| --- | --- | ---: | --- | --- |
| 分组标题 | SC Medium | 18 | 淡青白 | 无描边，最多 1px 暗青阴影 |
| 左侧标签 | SC Regular/Medium | 18~20 | 冷白 | 无黑色外圈 |
| 按钮主文字 | SC Medium | 16~18 | 白色 | 轻微暗青偏移阴影 |
| 按钮副标题 | 拉丁 Regular | 10~12 | 低饱和青灰 | 不使用对白描边 |
| 滑块刻度 | Regular | 11~13 | 青灰白 | 无描边 |
| 底部导航 | SC Medium | 15~16 | 白色 | 轻微阴影 |

优先修正 TTC face index，确保中文标签使用 SC face。`.ttc` 当前如果固定打开 face 0，可能使用日文字形，这会让中文部件比例看起来不统一。建议支持：

```text
WA2_FONT_FACE=2
```

并在启动日志中打印实际字体族名和 face index。

设置界面还应关闭或大幅降低对白专用的 `WA2_FONT_GAIN` 和 `WA2_FONT_BOLD`。菜单文字的清晰度应来自正确字号、正确 face 和干净底图，而不是把覆盖率推到很高。

## 四、不要用真实空格模拟中文字距

当前 `spread_cjk` 通过在每个汉字之间插入 ASCII 空格来模拟原版的字距。这个方法会改变排版度量，并造成截图中左侧标签和按钮文字显得过松：

```text
画 面 模 式
```

建议改为真正的 tracking：

```text
glyph_x += glyph_advance + tracking_px
```

推荐初始值：

- 左侧标签：`0~1` 逻辑像素；
- 分组标题：`1` 逻辑像素；
- 按钮文字：`0` 或 `0.5` 逻辑像素；
- 四字页签：根据实际宽度居中，不插入空格。

tracking 必须在窗口缩放前按逻辑坐标计算，再乘窗口比例。不要把空格放进字符串，否则居中、裁剪和宽度测量都会出现误差。

## 五、统一基线和垂直节奏

截图中的部分标签并不是字形本身难看，而是文字位于控件中的高度不一致：有的靠近上边，有的压到分隔线，有的副标题距离主标题太近。

建议所有设置界面文字使用显式 baseline，而不是只把文字纹理放进矩形后做简单居中：

```text
baseline = box_top + (box_height - ascender - descender) / 2 + ascender
```

不同元素使用固定的逻辑行高：

```text
分组标题：18~20
普通标签：28~30
按钮单行：36
按钮双行：主文字 20 + 副文字 12，中间保留 3~4
滑块刻度：16~18
```

特别注意以下几组当前容易互相干扰的区域：

- `画面设置` 与第一条规则线；
- `文本设置` 与第一行按钮；
- `视觉设置` 与第一行透明度控件；
- `0%/100%` 与滑块轨道；
- 底部 `上一页 / OPTION / 下一页` 三行文字。

每个区域应先画几何结构，再画文字，最后做一次边界检查，确认文字 ink bounding box 没有越过规则线和按钮边框。

## 六、重新安排滑块和刻度

截图中滑块的功能已经可用，但视觉上显得拥挤。建议把滑块分成明确的几何层：

```text
左箭头 | 轨道 | 右箭头
        0%              100%
```

具体调整：

- `0%` 和 `100%` 放在轨道下方，左右边缘对齐到实际可点击范围；
- `FAST`、`SLOW` 与百分比使用不同的垂直行，不要叠在轨道边缘；
- 关闭按钮如“窗口 OFF”独立放在轨道左侧，不要与 0% 共用视觉位置；
- 当前值的填充只覆盖轨道内部，不要让 cyan 图层覆盖刻度文字；
- 选中态用亮度变化和短高光表示，避免整条控件同时发白。

轨道段数、可点击范围和绘制范围应由同一组常量计算，避免 `BAR_SEGMENTS`、`x0/x1` 和鼠标命中矩形出现偏差。

## 七、修正状态层的颜色和透明度

截图中选中按钮的青色填充过亮，白字、亮框和青色洗色叠加后失去层次。建议采用三档明确状态：

```text
idle       深青黑底 + 低亮边框
selected   中等青色底 + 白字 + 细亮边框
hover      选中态基础上增加局部高光，不改变整体底色
```

建议：

- selected body alpha 约 `110~150`；
- hover body alpha 约 `60~100`；
- 白色文字不参与 tint；
- 高亮边框只画 1~2 像素，不要扩大整个按钮的白色区域；
- 状态层绘制完后再画文字，避免亮度阈值把文字颜色污染。

对于 `fill_option_body`，不要通过 `lum >= 230` 猜测文字位置来保护字。应直接使用文字 mask，或者先画状态底色、后画文字，顺序上彻底避免互相覆盖。

## 八、底部导航和页签单独设计

顶部 `OPTION 1/2/3` 和底部 `上一页 / OPTION / 下一页 / 恢复默认设置` 是界面最容易暴露“不统一”的区域。建议：

- 页签文字使用统一的英文小型标题风格，字号固定，三项在同一基线；
- 当前页签使用亮青填充，其他页签使用低对比度深青；
- 底部中间的说明文字和 `OPTION` 副标题使用两种明确字号；
- `恢复默认设置` 按钮的文字垂直居中，避免被原素材横条裁掉；
- 导航箭头、页签和默认按钮都使用独立的 clean mask，不要统一调用页面擦字函数。

如果原版素材中的英文标题已经清晰，也可以保留英文图层，只替换中文标签。不要在同一位置同时留下原版英文、修补后的暗影和新中文三层文字。

## 九、建议的实现顺序

1. **生成 clean 页面缓存**：先解决旧文字残留和 `nearby_fill` 碎点，这是截图中最脏的部分。
2. **修正 TTC face index**：确认中文使用 SC face。
3. **移除 `spread_cjk` 的真实空格**：改为 tracking 参数。
4. **独立菜单字体样式**：关闭对白式粗描边，降低 gain，使用轻微阴影。
5. **重排基线和滑块刻度**：确保文字不压线、不撞按钮、不越出轨道。
6. **重做状态合成顺序**：底图 → 状态层 → 文字层，删除用亮度阈值保护文字的逻辑。
7. **最后调整颜色**：在几何和文字干净后再微调 cyan、白色和阴影的色值。

## 十、验收标准

设置界面应在 1280×720、1920×1080 和 2560×1440 分别检查，并覆盖三页、默认态、选中态、悬停态和滑块不同数值。

重点检查：

- 左侧标签周围没有碎点、旧字和青色残影；
- 按钮内部只有一套文字；
- 中文字形统一为正确的 SC face；
- 四字标题不因插入空格而过松；
- 文字不会碰到规则线、边框和滑块轨道；
- 选中态、悬停态和空闲态具有明显但克制的层次；
- 页签和底部导航与主页面使用同一套字重和基线；
- 设置状态变化时不会重新执行整页像素修补。

建议用 `WA2_MENU_DUMP` 导出每个状态的 TGA，固定比较以下状态：

```text
page1/default
page1/hover-slider
page1/selected-button
page2/default
page3/default
page3/hover-row
```

改动后运行：

```bash
cargo build --release
cargo test
```

这套界面的首要目标是“干净、统一、可读”，之后再追求更强的发光效果。当前截图最需要减少的是残留和叠加，而不是继续增加文字亮度。

## 落实情况（2026-10-19 接手后）

> 本节记录按本方案执行后的实际改动与验证结果；上文是原方案，未改。

### 一、清洁底图 + 烘焙缓存（方案 §1、§2、§9-1）
- 新增 `data/cache/ui/menu/page{1,2,3}_clean.tga` 与 `page{1,2,3}_hover.tga`，由 `wa2-native menu-clean` 生成（已接进 `tools/build_ui_cache.py`，素材变更后跑一次即可）。
- `bake_clean_page`：先跑一次 `wipe_baked_captions`，随后按**固定矩形 + 颜色模型**重建（不再逐像素猜）：
  - 左列标签区：背景纯黑；标题竖条/分隔线用「暗青 + 连续 8px 以上 run」判据保留，日文标签、点线全部清掉；
  - 滑轨下方的 FAST/SLOW/0%/100%/MIN/MAX：整段清黑（原版烘焙的数值条也在此段，必须一起清）；箭头按钮矩形跳过；
  - 选项按钮内部：按列取中位数当底板色，偏离超过阈值即视为文字清掉（保留左右雪花）。
- `bake_clean_state`：hover/selected 状态表（`sys_0321X`）只保留外框，内部底板从 clean 页复制，因此不会再有「状态表烘焙文字透出来」的第二层字。
- 运行时：`Assets` 优先 blit 缓存页并**跳过整页擦字**；只有缓存缺失时才跑旧的 `wipe_baked_captions` 兜底（方案 §2 的降级路径）。
- 页签（`sys_03011`）、默认按钮（`sys_03030`）、帮助行（`sys_0304X`）本身已带**中文/英文烘焙文字**，改为原样使用、不再重画；此前 `flatten_pill` 会留下灰带、帮助行会出现两层字。

### 二、字体样式（方案 §3、§4、§5）
- 菜单文字使用独立 `ink` 调色板（标题淡青、标签冷白、按钮白、副标题青灰、刻度青灰白、导航白），不再继承对白的三层描边；SC face 2 在字体美化阶段已默认。
- `spread_cjk`（插空格模拟字距）删除，改真 tracking：`Label.tracking` + `measure_tracked`，按逻辑像素计算后随窗口缩放；顺带修掉 `stamp_buf` 的 off-by-one（第一段间隙没加 tracking，导致「量出来的宽度」和「画出来的宽度」差一段）。
- 所有标签走显式 baseline（字体行高居中，box 过矮时才退回 ink 居中），并有 `every_label_stays_inside_its_box` 守住三页所有标签不越框。
- 字距：标题 1px，行标签 0，按钮 0，刻度 0；按钮副标题用独立字号（11），不再由主字号折算。

### 三、状态层与配色（方案 §7）
- `fill_option_body` 删除 `lum >= 230` 的文字保护猜测（文字在状态层之后画，不需要猜）；选中 body alpha 175→132，悬停 90→80，三档状态（idle/selected/hover）层次更克制。
- 状态表只提供边框和 body wash，文字永远是最后画的一层。

### 四、滑块与导航（方案 §6、§8）
- FAST/SLOW/0%/100%/MIN/MAX 移到轨道下沿（`sl.y + BAR_H + 2`，10px，青灰色），与轨道/箭头不再交叠；坐标 bug 修正（此前 `BAR_X0 - PAGE_X` 被 `tiny()` 再加一次 `PAGE_X`，标签跑到轨道左边）。
- 底部导航：`环境设置 / OPTION` 用固定字号与基线；`恢复默认设置` 用原版烘焙中文按钮（带齿轮，三态齐全），不再 flatten。
- 页签保留原版 `OPTION 1/2/3` 烘焙英文（与引擎要显示的文字一致，三态颜色由原表提供）。

### 五、重要发现：4x 素材树的 UI 页有上采样伪影
- 声音设置页的 `音量ON/OFF` 药丸在 `bg_cn_4x/sys_03101.webp` 里文字被上采样器糊成竖条，而 1x（`bg_cn/sys_03101.tga`）与 8x 都是好的。
- 因此设置界面的图源固定 **1x 优先**（`Assets::load` 把 `_4x` 目录放最后；`menu-clean` 也从 1x 树烘焙）。4x 树继续只服务场景美术。

### 验证
- `cargo build --release` / `cargo test`：**76 通过**（新增菜单相关测试：标签不越框、tracking、烘焙页残留/结构保留、clean 页无需擦字等）。
- `WA2_MENU_DUMP` 在 1280×720 / 1920×1080 / 2560×1440 抓了 page1/2/3 的默认、hover、选中态：左列无碎点/旧字，按钮内只有一套文字，刻度不压轨道，页签/导航/默认按钮与原版一致。
- 缓存生成：`python3 tools/build_ui_cache.py`（约 10 s），或在引擎构建后跑 `./target/release/wa2-native menu-clean`。

### 仍留的取舍
- 页签/默认按钮/帮助行用的是原版烘焙字体（与 Noto 略有差异），换取 100% 原版观感与零修补；如果以后要求全 Noto，可在这三处做同样的「清内部 + 矢量重画」。
- 底部导航条仍是每帧 `repaint_from_column` 擦一次（区域很小，几毫秒）；可后续烘焙成 cache。
